# BL2FLP — BandLab → FL Studio

Переносит структуру проекта BandLab (дорожки, клипы, MIDI-ноты, drum-паттерны,
громкость/панораму, эффекты) в нативный `.flp` и собирает VST3-плагин с
моделированными эффектами.

Проект не выдаёт себя за официальный конвертер BandLab. Ограничения перечислены
ниже и дублируются в отчёте каждого преобразования (`*.report.json`).

## Что работает

- Разбор локального JSON-манифеста ревизии BandLab и ZIP-архива с манифестом и
  аудиофайлами.
- Аудио-клипы: канал Sampler на каждый клип, абсолютный путь к файлу, позиция,
  длительность, громкость/панорама дорожки, mute.
- MIDI-дорожки: паттерн Piano Roll на каждый клип, ноты с velocity, позицией и
  длительностью; паттерн-блок ставится на таймлайн.
- Drum-machine: шаги `steps` разворачиваются в MIDI-ноты с сеткой 1/16.
- Плейлист FL Studio 2026: 88-байтовые записи (формат проверен по файлам,
  сохранённым самим FL Studio 2026).
- Громкость/панорама каналов, роутинг каналов на инсерты, имена каналов и
  паттернов, темп, размер, название проекта.
- MIDI-файл всей аранжировки как переносимый резерв.
- `.blwb` — 76-байтовые состояния эффектов для плагина (общий контракт Python/C++).
- VST3 + Standalone: FDN-реверб, BBD-хорус, feedback-компрессор, гитарный
  усилитель с темброблоком, загрузка `.blwb`.

## Ограничения (важно)

- **Нет загрузки из облака BandLab.** Публичного стабильного API с документированной
  схемой ревизии нет; endpoint’ы web-клиента не документированы. Манифест нужно
  выгрузить из вкладки Network (см. ниже). Конвертер не притворяется, что умеет
  скачивать проекты по ссылке.
- **Автоматизация не создаётся нативными Automation Clip.** Точки читаются и
  попадают в отчёт, но в `.flp` не записываются. Это следующий этап.
- **Fader’ы инсертов не выставляются.** В шаблоне `Empty.flp` у пустых инсертов
  нет параметров микшера; громкость/панорама переносятся на каналы Channel Rack,
  роутинг — на инсерты 1..16. Проекты с более чем 16 дорожками маршрутизируются
  на последний доступный инсерт (в отчёте будет `insert-overflow`).
- **Обрезка аудио-клипов (`sampleOffset`) не проверена на слух.** Смещение
  записывается в `start_offset`; для точной проверки нужен реальный проект
  BandLab с обрезанными клипами.
- **Плагин — моделирование, а не декомпиляция BandLab.** Алгоритмы написаны с
  нуля по описанию signal flow; бит-в-бит совпадения с BandLab нет. AutoPitch и
  Drum Machine не реализованы.
- **`.blwb` не встраивается в микшер автоматически.** Состояние эффектов лежит
  рядом с `.flp`; в плагине нажмите `Load .blwb state`.
- **DSP плагина проверен сборкой и запуском Standalone (UI, 16 ручек); аудио-рендер
  и загрузка `.blwb` в хосте не выполнялись.**
- **Проверка в FL Studio:** прототип с клонированными каналами и паттерном
  открывался в FL Studio 2026 (видны название проекта и `Pattern 1`). Плейлист
  проверен побайтово по формату FL 2026, но финальный проект не удалось открыть
  повторно: FL Studio в тестовой среде перестал создавать главное окно (в том
  числе без файла). Это ограничение среды проверки, а не подтверждённый дефект
  конвертера.

## Установка

```powershell
python -m pip install -r requirements.txt
```

Нужен Python 3.10+ (проверено на 3.14; для pyflp применяется совместимостный
шим). Для конвертации `.m4a/.aac/.opus` нужен `ffmpeg` в `PATH`.

## Запуск

```powershell
.\BL2FLP.cmd
```

Открывается окно: манифест, папка assets, выходной `.flp`, шаблон FL Studio.
Шаблон определяется автоматически из установленной FL Studio; можно указать
свой `Empty.flp`.

CLI:

```powershell
python -m bl2flp revision.json Output.flp --assets .\assets
python -m bl2flp revision.zip Output.flp
python -m bl2flp --show-template
```

Ключи: `--template`, `--positions auto|seconds|ticks`, `--no-midi`, `--no-states`.

## Как получить манифест BandLab

1. Откройте проект в веб-студии BandLab.
2. DevTools (`F12`) → Network → фильтр `revisions`.
3. Сохраните JSON-ответ как `revision.json`.
4. Скачайте исходные аудиофайлы (меню проекта → Download → Tracks) в `assets/`.

Имена полей в разных версиях клиента отличаются; парсер понимает
`tracks/trackList`, `regions/clips/segments`, `startPosition/start/startTime`,
`notes/midiNotes`, `samples/assets/files` и сообщает о каждом допущении в отчёте.

## Сборка плагина

```powershell
.\build-plugin.ps1
.\install-plugin.ps1 -UserOnly   # без администратора
# или
.\install-plugin.ps1             # в C:\Program Files\Common Files\VST3
```

Требования: Visual Studio Build Tools с C++ и Windows SDK, CMake, JUCE 8.0.6
(скрипт клонирует в `vendor/JUCE`).

Артефакты:

```text
build\BandLabWhiteBox_artefacts\Release\VST3\BandLab WhiteBox Suite.vst3
build\BandLabWhiteBox_artefacts\Release\Standalone\BandLab WhiteBox Suite.exe
```

После установки: FL Studio → Options → Manage plug-ins → Find more plug-ins.

## Состояние эффектов `.blwb`

Формат: little-endian `<4sII16f>`, 76 байт.

| Поле | Смещение | Значение |
|---|---|---|
| magic | 0 | `BLWB` |
| version | 4 | `1` |
| activeMask | 8 | битовая маска модулей |
| params[16] | 12 | нормализованные 0..1 |

Индексы параметров: 0–3 реверб, 4–5 хорус, 6–9 компрессор, 10–15 усилитель.
Python: `bl2flp/vststate.py`; C++: `StateChunk` в `plugin/Source/PluginProcessor.cpp`.

## Структура

```text
bl2flp/
  bandlab.py    разбор манифеста и units
  flp.py        запись .flp (88-байтовый плейлист, паттерны, каналы)
  midi.py       MIDI fallback
  vststate.py   .blwb
  pipeline.py   поиск шаблона, оркестрация, отчёт
  cli.py        CLI
  gui.py        Tkinter
plugin/Source/  VST3 (JUCE)
CMakeLists.txt  сборка плагина
```
